คู่มือการเสนอไอเดียและการปรับปรุงโปรเจกต์
Conversational Commerce Platform
==================================================

วัตถุประสงค์
------------
คู่มือนี้ใช้สำหรับแจ้งไอเดีย ปัญหา Feature ใหม่ หรือการแก้ไข Business Rule
เพื่อให้สามารถนำข้อมูลไปวิเคราะห์ต่อเป็น:
- Requirement
- Business Rule
- Workflow
- Database / ER Diagram
- Architecture
- เอกสาร .md ของโปรเจกต์

หลักสำคัญ
---------
คุณไม่จำเป็นต้องเขียนเป็นภาษาทางเทคนิค
ให้เล่าจาก "ปัญหาที่เกิดจริง" และ "สิ่งที่อยากให้ระบบทำ"
ส่วนการแปลงเป็น Business Rule, Database และ Architecture จะทำในขั้นวิเคราะห์

==================================================
5) สถานะของ Requirement / Rule
==================================================

IDEA
= เป็นเพียงแนวคิด

UNDER REVIEW
= กำลังวิเคราะห์ข้อดี ข้อเสีย และผลกระทบ

PROPOSED
= มีรูปแบบที่แนะนำแล้ว รอการยืนยัน

APPROVED
= ตกลงให้ใช้เป็นกติกาของระบบ

IMPLEMENTED
= พัฒนาใช้งานแล้ว

REJECTED
= ตัดสินใจไม่ใช้

==================================================
10) หลักการของโปรเจกต์นี้
==================================================

ก่อนเพิ่ม Feature ใหม่ ต้องถามว่า:

- Feature นี้แก้ปัญหาอะไร
- ใครเป็นผู้ใช้
- ใช้ตอนไหน
- ถ้า Feature ล้มเหลวเกิดอะไรขึ้น
- กระทบ Stock หรือ Order หรือไม่
- กระทบข้อมูลลูกค้าหรือไม่
- กระทบหลาย Channel หรือไม่
- มี Platform Policy จำกัดหรือไม่
- จำเป็นต้องทำตอนนี้หรือทำภายหลังได้
- ทำให้ระบบซับซ้อนโดยไม่จำเป็นหรือไม่

เป้าหมาย:
"Build Small, Design Big"

สร้างทีละส่วน
แต่ Architecture และ Data Model ต้องไม่ปิดทางการขยายในอนาคต
